## 1. The "Zero Trust" AI Interaction Model

### Core Rule: AI is an Untrusted Contributor
Treat all AI-generated code as if it were a submission from an external, unverified open-source contributor. It must pass the same (or stricter) scrutiny as junior developer code.

* **Isolation:** AI agents in Antigravity IDE operate in a sandboxed environment. They cannot access production secrets, live databases, or customer PII.
* **No Auto-Commit:** AI may *propose* changes (via pull requests or diffs), but it must **never** have direct push access to `main` or `release` branches.
* **The 30-Minute Rule:** If an AI-generated security patch takes more than 30 minutes to verify manually, reject it and rewrite. Complexity hides vulnerabilities.

## 2. Supply Chain Defense (Anti-Hallucination)

AI models often "hallucinate" package names (e.g., suggesting `npm install secure-auth-v5` when only `v4` exists, or inventing a library entirely). This is a vector for **Dependency Confusion Attacks**.

### The Verification Protocol
Before accepting any AI-suggested dependency:
1.  **Existence Check:** Verify the package exists on the official registry (npm, Maven, CocoaPods, Crates.io, PyPI).
2.  **Reputation Check:**
    * **Age:** > 1 year old?
    * **Downloads:** > 10k weekly downloads?
    * **Maintenance:** Last commit within 6 months?
3.  **Lockfile Integrity:** The AI must update `package-lock.json` / `yarn.lock` / `Podfile.lock` immediately to pin the version.

**🚫 Forbidden:**
* Installing packages from absolute URLs or git repositories suggested by AI without manual review.
* Running `curl | bash` scripts generated by AI.

## 3. Secrets & Credential Hygiene

### Absolute Prohibition
The AI must **NEVER** see, generate, or store:
* API Keys (AWS, Stripe, Firebase, OpenAI)
* Database Connection Strings
* Private Certificates / Signing Keys
* Hardcoded Passwords

### The ".env" Mandate
* **Detection:** If the AI detects a hardcoded secret in your legacy code, it must flag it immediately and suggest moving it to `.env`.
* **Generation:** All new code must access secrets via environment variables:
    * *Node.js:* `process.env.DB_PASSWORD`
    * *Python:* `os.getenv("DB_PASSWORD")`
    * *Android:* `BuildConfig.API_KEY`
    * *iOS:* `ProcessInfo.processInfo.environment["API_KEY"]`

## 4. Platform-Specific Vulnerability Mitigation

### 📱 Mobile (iOS & Android)
* **Insecure Data Storage:**
    * *Rule:* Never store tokens in `UserDefaults` or `SharedPreferences`.
    * *AI Enforcement:* Must use `Keychain` (iOS) or `EncryptedSharedPreferences` (Android).
* **Deep Links:**
    * *Rule:* Validate all URL parameters from deep links to prevent intent hijacking.
* **Screen Caching:**
    * *Rule:* Mask sensitive fields (credit cards, passwords) so they don't appear in the OS app switcher screenshot.

### 🌐 Web (SPA/SSR)
* **XSS (Cross-Site Scripting):**
    * *Rule:* Ban `dangerouslySetInnerHTML` (React) or `v-html` (Vue) unless explicitly wrapped in a sanitizer (e.g., DOMPurify).
* **CSRF (Cross-Site Request Forgery):**
    * *Rule:* Ensure all state-changing endpoints (POST/PUT/DELETE) require Anti-Forgery tokens.
* **CSP (Content Security Policy):**
    * *Rule:* AI must generate a strict CSP header for all new pages.

### 🖥️ Desktop (Electron/Tauri/Native)
* **RCE (Remote Code Execution):**
    * *Rule:* Electron `nodeIntegration` must be set to `false`. `contextIsolation` must be `true`.
* **Privilege Escalation:**
    * *Rule:* The application must never request "Run as Administrator" / "sudo" unless strictly necessary for installation.

## 5. Automated Security Gates (SAST/DAST)

Integrate these tools into the Antigravity IDE workflow. The AI should be trained to read their output and propose fixes.

* **Static Analysis (SAST):**
    * *Mobile:* MobSF (Mobile Security Framework)
    * *Web:* SonarQube / ESLint Security Plugin
    * *Infrastructure:* Checkov (for Terraform/Docker)
* **Secret Scanning:**
    * *Tool:* TruffleHog or GitGuardian.
    * *Action:* Blocks any commit containing high-entropy strings resembling keys.
* **Dependency Scanning:**
    * *Tool:* OWASP Dependency-Check or Snyk.
    * *Action:* Fails the build if a package has a CVE with score > 7.0.

## 6. Data Privacy & PII Handling

### The "Clean Context" Rule
Never paste real PII (Personally Identifiable Information) into the AI chat context.
* **Bad Prompt:** "Fix this JSON error: `{"user": "john.doe@gmail.com", "cc": "4242..."}`"
* **Good Prompt:** "Fix this JSON error: `{"user": "<REDACTED_EMAIL>", "cc": "<REDACTED_CC>"}`"

### GDPR/CCPA Compliance
* **Right to be Forgotten:** AI-generated database schemas must include a "soft delete" column or a dedicated "purge user" script.
* **Data Minimization:** AI should suggest schema optimizations that remove unnecessary data collection fields.

## 7. Incident Response & Audit Trails

### If the AI Introduces a Vulnerability:
1.  **Stop:** Halt all AI code generation immediately.
2.  **Isolate:** Revert the specific commit SHA.
3.  **Tag:** Mark the prompt that generated the bad code with `#SECURITY_FAIL` in the IDE history.
4.  **Retrain:** Update the `vibe-coding-guidelines.md` "Anti-Patterns" section with the specific failure case.

## 8. Security Prompts & Checklists

### 🛡️ Security Review Prompt
*Use this when asking the AI to review code it (or you) just wrote.*

```markdown
**Role:** Senior Security Engineer.
**Task:** Perform a security audit on the following {LANGUAGE} code snippet.
**Context:** This code handles {FUNCTIONALITY} (e.g., User Login, File Upload).

**Checklist:**
1. [OWASP Top 10] Check for Injection (SQL, Command, LDAP).
2. [Auth] Verify broken authentication or session management.
3. [Data] Check for exposure of sensitive data (logs, error messages).
4. [Access] Validate function-level access control.
5. [Dependencies] Flag any insecure or unnecessary imports.

**Output:**
- List of Critical/High/Medium vulnerabilities.
- Specific line numbers.
- Refactored, secure code block.
